# API reference

Every route is under `/api`. Request bodies are JSON (validated with zod; the first problem comes back as a 400 `{ error }`), money is integer paise, and ids are MongoDB ObjectId hex strings.

| Method          | Path                                                             | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET             | `/api/categories`                                                |                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| GET             | `/api/search/suggest?q=`                                         | Up to 3 matching `categories`, the 6 best `products` (`slug`, `title`, `brand`, `price`) and the `total` that match                                                                                                                                                                                                                                                                                                                               |
| GET             | `/api/products`                                                  | `q`, `category` (slug), `brand` (comma-separated), `minPrice`/`maxPrice` (paise), `rating`, `inStock=1`, `sort`, `page`, `pageSize` ≤48; with no results for `q`, `suggestion: { q, total }` (or null)                                                                                                                                                                                                                                            |
| —               | `deals=1` and `sort=discount` on `GET /api/products`             | `deals=1`: only products at least `DEAL_PERCENT` (40) below their MRP, or in a running sale; `sort=discount`: biggest discount (MRP against price) first. Both combine with the other filters                                                                                                                                                                                                                                                     |
| —               | `size=` on `GET /api/products`                                   | Comma-separated sizes (stage 109): only products with one of them in stock. The response's `sizes` lists the sizes in stock among the results (ignoring this filter), `[{ name, count }]` in size order                                                                                                                                                                                                                                           |
| —               | `spec=Name:Value` on `GET /api/products`                         | Repeated (stage 138): values of one name are alternatives, names must all match, ignoring case. The response's `specs` lists shared specifications among the results, `[{ name, values: [{ value, count, chosen }] }]`, each name's counts ignoring its own choices                                                                                                                                                                               |
| GET             | `/api/dispatch`                                                  | Ship-today countdown (stage 139): `dispatch` is `{ shipsToday: true, cutoffAt }`, `{ shipsToday: false, shipsOn, tomorrow }` or null when off; admins read and set `{ enabled, cutoff, days }` at `/api/admin/dispatch`                                                                                                                                                                                                                           |
| POST            | `/api/news/unsubscribe?token=`                                   | Store news (stage 140): stops store news for the account with that token (from the email's link or a mail app's one-click unsubscribe); 404 for an unknown token. Admins write and send at `/api/admin/newsletters` (list, POST, PUT/DELETE drafts, `/:id/test`, `/:id/send`); customers opt in with `newsEmails` on `PUT /api/account/email-preferences`                                                                                         |
| GET             | `/api/admin/newsletters/group?group=`                            | Store news groups (stage 143): `{ group, label, count }` of subscribers in `all`, `loyalty:silver`, `loyalty:gold`, `tag:<tag>` or `category:<id>`; newsletters take `group` when saved                                                                                                                                                                                                                                                           |
| PUT             | `/api/account/birthday`                                          | Birthday treat (stage 141): `{ birthday: { month, day } }` or `{ birthday: null }`. `GET /api/birthday-treat` says whether treats are on (`{ amount, minOrder, validDays }` or null); admins read and set them at `/api/admin/birthday`                                                                                                                                                                                                           |
| PUT             | `/api/wishlist/:productId/target`                                | Price alert (stage 142): `{ targetPrice }` (paise, whole rupees, below the current price) or `{ targetPrice: null }`; the product must be on the wishlist. `GET /api/wishlist` items carry `target` (`{ price, reachedAt }` or null)                                                                                                                                                                                                              |
| GET/POST/DELETE | `/api/saved-searches`, `/api/saved-searches/:id`                 | Saved searches (stage 144, logged in): POST `{ search }` (the search page's query string; prices in rupees) saves it (≤10; the same search again returns the existing one); GET lists `{ items: [{ id, label, path, createdAt }], max }`                                                                                                                                                                                                          |
| GET             | `/api/review-rewards`                                            | Review rewards (stage 145): `{ amount, minChars, settleDays }` while on, else null; admins read and set `{ enabled, amount, minChars, monthlyCap }` at `/api/admin/review-rewards`                                                                                                                                                                                                                                                                |
| GET             | `/api/pickup-points`                                             | Click and collect (stage 146): the active pickup points. `POST /api/orders` takes `pickupPointId` + `contact` `{ name, phone }` instead of `address`, the quote `pickup=1`; admins manage points at `/api/admin/pickup-points` (GET, POST, PUT `/:id`) and mark a pickup order collected with `pickupCode` on the status route                                                                                                                    |
| —               | `fit` on `PUT /api/products/:slug/review`                        | `small`, `true`, `large` or null (stage 137), only for products with a Size or Waist option. `GET /api/products/:slug` returns `sizeFit` `{ small, true, large, total, verdict }` from 3 answers among visible reviews, else null                                                                                                                                                                                                                 |
| GET             | `/api/products/:slug`                                            | Full product with images, highlights and category                                                                                                                                                                                                                                                                                                                                                                                                 |
| GET             | `/api/products/:slug/related`                                    | Up to 8 similar product cards: same category and brand first, then category, then brand; in stock first, then by popularity                                                                                                                                                                                                                                                                                                                       |
| GET             | `/api/products/:slug/bought-together`                            | Up to 6 product cards bought in the same orders as this one by at least 2 different customers (sales only; shown and in stock), most customers first                                                                                                                                                                                                                                                                                              |
| GET             | `/api/recently-viewed?slugs=`                                    | Cards for up to 10 product slugs (comma-separated) in that order; hidden or unknown products left out                                                                                                                                                                                                                                                                                                                                             |
| GET             | `/api/add-ons?ids=`                                              | The add-ons of these products (the cart's product ids, ≤20) that are shown, in stock and not among them, in cart order then each product's own: `{ items: [card] }` (≤8). `GET /api/products/:slug` returns its own as `addOns` (cards); admins set `addOns` (≤6 product ids) on product create/PATCH                                                                                                                                             |
| GET             | `/api/cart`                                                      | `items=<productId>[.<variantId>]:<qty>,…` (≤20 items, qty ≤10; a product with variants needs one): current prices, stock problems, bundle savings (`itemsTotal`, `bundles`, `bundleSaving`; `subtotal` is after them), delivery and total, and `cashback` `{ amount, percent }` when it's on. | GET             | `/api/admin/cashback`                                            | Admin: `{ enabled, percent, cap, since, paid: { total, orders } }`; `PUT` `{ enabled, percent (1–20), cap (paise) }` (switching on sets `since`)                                                                                                                                                                                                                                                                                                  |
| GET             | `/api/account/referral`                                          | The customer's referral link code and stats (`{ enabled: false }` when off); `/api/auth/register` and `quick-account` take `ref`, `/api/cart` takes `&ref=` and returns `referral` `{ discount }`                                                                                                                                                                                                                                                 |

| GET             | `/api/admin/size-guides`                                         | Admin: every guide; `POST` / `PUT …/:id` `{ name, table (text), note?, categoryIds }`, `DELETE …/:id`; products take `sizeGuide` (an id, `'none'`, or null for the category's)                                                                                                                                                                                                                                                                    |
| POST            | `/api/auth/login`                                                | `{ email, password }`; sets the `sid` session cookie (httpOnly, 30 days), and for admins the `bazaar_device` cookie, emailing them on a browser their account hasn't used before; with two-step login on → `{ user: null, twoStep: true, ticket }` (5 minutes)                                                                                                                                                                                    |
| POST            | `/api/auth/login/code`                                           | `{ ticket, code }` (app code or recovery code) → `{ user, recoveryCodesLeft }` and the session; 5 wrong codes end the ticket (429)                                                                                                                                                                                                                                                                                                                |
| POST            | `/api/auth/logout`                                               | Ends the session                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| POST            | `/api/auth/forgot-password`                                      | `{ email }` → 204 either way; emails a one-time reset link (1 hour, at most 3 an hour) if the account exists                                                                                                                                                                                                                                                                                                                                      |
| POST            | `/api/auth/email-code`                                           | `{ email }`: emails a 6-digit login code if the account exists; always 204 (3 an hour per account). `POST /api/auth/email-code/login` `{ email, code }` logs in (or returns a two-step ticket); 401 wrong, 429 after 5 wrong tries or 30 tries an hour per network, 400 expired or replaced                                                                                                                                                       |
| POST            | `/api/auth/reset-password`                                       | `{ token, password }`: sets the password, logs out every device, logs this browser in → `{ user }`; with two-step login on → `{ user: null, twoStep: true }` and no session                                                                                                                                                                                                                                                                       |

| POST            | `/api/account/addresses`                                         | Login. `{ address, label? }` (same rules as checkout; label ≤30) → 201 `{ user }` with `addresses` (default first) and `address` (the default); 409 if already saved or 10 are kept                                                                                                                                                                                                                                                               |
| PUT             | `/api/account/addresses/:id`                                     | Login. `{ address, label? }` edits one → `{ user }`; `DELETE` removes one (the next becomes the default); `POST …/:id/default` makes it the default                                                                                                                                                                                                                                                                                               |
| PUT             | `/api/account/email-preferences`                                 | `{ priceDropEmails?, cartReminderEmails?, reviewReminderEmails? }`: switches those emails on or off (the user object has them all, on unless switched off)                                                                                                                                                                                                                                                                                        |
